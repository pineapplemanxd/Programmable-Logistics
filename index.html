PLang Language Documentation

Welcome to PLang (Programmable Logistics Language), a simple C-like language designed specifically for scripting automation and logistics networks in Minecraft.

Basic Syntax

PLang uses a familiar syntax inspired by C, C++, and Java. - Variables: Statically typed, e.g. int count = 5; or string name = "hello"; - Control Flow: if / else, while, for, break, continue - Comments: // single line or /* multi-line */

Example

int main() {
    int i = 0;
    while (i < 10) {
        log::info("Iteration: {}", i);
        i++;
    }
    return 0;
}

Built-in Types

  • int / long: 64-bit integer
  • bool: Boolean value (true or false)
  • string: Text strings (concatenated with +)
  • list<T>: A dynamic list of items (e.g., list<string>)
  • auto: Type inference based on assigned value
  • void: Used only as a return type for functions that don't return anything.

Headers and Built-ins

PLang code operates by including specific headers for the tasks you need.

#include <pl/log.hpp>

Provides server console logging. - log::info(string message, ...): Prints an info message to the server log.

#include <pl/inventory.hpp>

Provides commands to control inventories in the logistics network.

Getting an Inventory

// Finds the inventory attached to the alias "my_chest"
Inventory chest = inventory("my_chest");

Inventory Methods

  • int count(string itemId): Returns the total amount of a specific item in the inventory.
  • bool has_space(string itemId, int amount): Returns true if the inventory has space to receive the given amount of the item.
  • int slots(): Returns the total number of slots in the inventory.
  • string slot(int index): Returns the string ID of the item in the specified slot index (e.g. "minecraft:iron_ore"). Returns an empty string "" if the slot is empty or the index is out of bounds.

Transferring Items

  • int transfer(Inventory source, Inventory target, string itemId, int amount): Moves up to amount of itemId from the source inventory to the target inventory across the network. Returns the actual amount successfully moved.

#include <pl/screen.hpp>

Provides commands to draw to a Programmable Screen block.

Getting a Screen

// You must use a Programmable Controller to draw to a Screen!
// Find the screen attached to the network with the given alias:
Screen s = screen("dashboard_screen");

Screen Methods

  • clear(): Clears the drawing buffer.
  • flush(): Swaps the drawing buffer and sends the image to the screen. Must be called to see changes!
  • set_background(int color): Sets the background color using an integer hex code (e.g., 0x00FF00 for green).
  • text(int x, int y, string text, int color, int scale): Draws text at coordinates x,y.
  • rect(int x, int y, int w, int h, int color): Draws a filled rectangle.
  • outline(int x, int y, int w, int h, int color): Draws a hollow rectangle outline.
  • line(int x1, int y1, int x2, int y2, int color): Draws a line between two points.
  • progress(int x, int y, int w, int h, int current, int max, int color): Draws a progress bar.
  • width(): Returns the screen width in pixels (640).
  • height(): Returns the screen height in pixels (480).

Advanced Features

Timing & Yielding

PLang executes code per server tick. To prevent the server from lagging, the VM restricts how many instructions can run per tick. - sleep(int ticks): Pauses execution of the script for the specified number of ticks. - yield(): Pauses execution until the next tick.

Multi-File Workspaces

You can write code across multiple files in the WebGUI editor. - Local Files: Exist only on the block running the code. - Global Files: Shared across all Programmable Controllers on the server! Include them just like C headers:

#include "my_local_file.hpp"
#include <my_global_file.hpp>

Persistent Global Variables

Variables declared outside of functions are persisted. If the chunk unloads and reloads, global variables will retain their previous values!

Network Dashboard (#include <pl/dashboard.hpp>)

The Dashboard type allows you to run an HTTP server directly from the game to host a live dashboard accessible in a real web browser! You must place a Network Dashboard block and connect it to your network.

Getting a Dashboard

// Find the dashboard attached to the network with the given alias:
Dashboard dash = dashboard("main_dash");

Starting the Server

// Start the web server on a specific port (e.g., http://localhost:8080)
dash.start_server(8080);

Setting Widgets

// Display a value on the dashboard grid. The dashboard will automatically update in real-time!
dash.set_widget("Iron Stock", iron_inv.count("minecraft:iron_ingot"));
dash.set_widget("Status", "Running");

New Advanced Features (v1.1.0)

1. Chat Broadcaster (#include <pl/chat.hpp>)

Send messages directly to players!

auto chat = chat("my_broadcaster");
chat.broadcast("Warning: The furnace is completely out of coal!");
chat.whisper("Super", "Hey, your iron is done smelting!");

2. Redstone Interface (#include <pl/redstone.hpp>)

Read and emit Redstone power (0-15)!

auto rs = redstone("rs_door");
if (rs.get_input() > 0) {
    // A button was pressed next to the interface!
    rs.set_output(15); // Open the door!
}

3. Network Hard Drive / Database (#include <pl/database.hpp>)

Store huge amounts of strings permanently across server restarts!

auto db = database("main_drive");
db.set_string("status", "ACTIVE");
string s = db.get_string("status");

4. Energy Interface (#include <pl/energy.hpp>)

Connect to modded power cables and batteries.

auto eng = energy_interface("main_battery");
auto machine = energy_interface("furnace");
long stored = eng.get_energy_stored();
long max = eng.get_max_energy_stored();

// Transfer 50,000 FE from the battery to the furnace
transfer_energy(eng, machine, 50000);

Example: Checking the First Item in a Container

#include <pl/inventory.hpp>
#include <pl/log.hpp>

int main() {
    Inventory input = inventory("input_chest");

    // Check what is in the very first slot (slot 0)
    string firstItem = input.slot(0);

    if (firstItem != "") {
        log::info("The first item is: {}", firstItem);
    } else {
        log::info("The first slot is empty!");
    }

    return 0;
}
